<objective>
Make the current release checks authoritative across Bash, PowerShell, GitHub Actions, and image publication, while locking the dirty import, QQ, and authentication regression evidence into the same blocking gate.

Purpose: A passing local test that differs from CI or a publish workflow that can bypass CI leaves the production image unqualified. The existing pnpm lockfile, deterministic tests, reusable workflow, and publish dependency must describe one enforceable contract.

Output: Frozen local/Docker/CI gates, platform-parity verification helpers, import and QQ boundary regression tests, and a publish workflow that cannot authenticate to GHCR until Quality Gates passes. Preserve all existing dirty changes and do not create a walking skeleton.
</objective>

<threat_model>
## Security Level

OWASP ASVS L1. All High-severity threats are blocking and must be mitigated before this plan completes.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Package manifests/lockfile to local and Docker installers | Dependency resolution crosses from repository-controlled metadata into build tooling and generated assets. |
| Source/test fixtures to CI logs and artifacts | Synthetic credentials and upstream response bodies are processed by automated tests and workflow output. |
| GitHub event to workflow permissions | Push, pull request, manual, and reusable-call contexts select jobs with different token capabilities. |
| Quality workflow to publication job | A reusable workflow result controls whether registry authentication and image push may occur. |
| Compose interpolation to validation command | A placeholder APP_SECRET is required for config validation and must never be confused with production credentials. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / Supply Chain | pnpm lockfile, Dockerfile, local/CI installs | high | mitigate | Task 1 requires pnpm 10.4.0 and frozen-lockfile installs in scripts, Docker, and CI; no alternate resolver or mutable Docker install remains. |
| T-01-02 | Tampering / Elevation of Privilege | `.github/workflows/publish.yml` | high | mitigate | Task 3 preserves a reusable Quality Gates job and an explicit `needs: quality` edge before registry login/build/push; failures cannot be bypassed with success fallbacks. |
| T-01-03 | Information Disclosure | workflow permissions, Compose validation, test fixtures | high | mitigate | Task 3 grants quality read-only contents access, scopes package writes to publication, uses only a non-production placeholder for Compose, and bans real credentials from fixtures/output. |
| T-01-04 | Tampering / Repudiation | local-vs-CI quality contract | medium | mitigate | Tasks 1 and 3 make yaml.v3 syntax/semantic assertions and native security harnesses unconditional in local scripts and required Linux/Windows CI lanes; actionlint is supplemental only. |
| T-01-05 | Information Disclosure | import/QQ/auth regression fixtures | medium | mitigate | Task 2 uses local HTTP servers and synthetic values, asserts metadata redaction, and keeps Plan 01 auth rejection tests in the backend gate. |
| T-01-06 | Tampering | mutable upstream action major tags | medium | accept | Existing official GitHub Actions remain major-version pinned in this phase; digest pinning and provenance belong to the release-candidate/supply-chain scope, while least-privilege permissions and frozen application dependencies are enforced here. |
| T-01-07 | Denial of Service | quality job concurrency | low | accept | Superseded CI runs are already canceled by workflow concurrency; broader runner/resource policy is a repository administration concern and does not permit an unsafe publish because `needs: quality` remains blocking. |

## Package and Secret Handling

No new package is introduced and no lockfile is regenerated. Existing dependencies are installed only from the committed pnpm lockfile; all quality inputs use placeholders or synthetic fixtures. The workflow must never echo `GITHUB_TOKEN`, APP_SECRET, access tokens, cookies, or operator passwords.
</threat_model>
