<objective>
Make SQLite backup/restore a verifiable operational workflow instead of a best-effort file copy.
</objective>

<must_haves>
  - Backup captures a consistent SQLite database snapshot and config under one timestamped manifest.
  - WAL/SHM handling is explicit; a backup is either checkpointed/clean or preserves the complete SQLite sidecar set.
  - Restore validates the selected manifest, stops the app, restores atomically, removes stale sidecars, restarts, and checks health.
  - Both Bash and PowerShell entrypoints have the same command contract and safe path validation.
  - Tests use temporary fixtures and never touch the repository's live data directory.
</must_haves>

<tasks>
<task type="auto" tdd="true">
  <name>Task 1: Define manifest and consistency contract</name>
  <files>scripts/backup-data.sh, scripts/backup-data.ps1, scripts/backup_data_test.go</files>
  <action>Add a timestamped manifest containing file names, sizes, SHA-256 hashes, and SQLite checkpoint/sidecar state. Make backup fail closed when the database is absent or the manifest cannot be written. Keep credentials out of output and manifests.</action>
  <verify>go test ./scripts -run 'Backup|Restore' -count=1</verify>
</task>
<task type="auto" tdd="true">
  <name>Task 2: Make restore atomic and verifiable</name>
  <files>scripts/backup-data.sh, scripts/backup-data.ps1, scripts/backup_data_test.go, docs/FORK_NOTES.md</files>
  <action>Restore only a validated manifest, stage database/config replacements beside live files, replace atomically, remove stale WAL/SHM, restart Compose when available, and require /healthz=200. Provide dry-run/list/verify output for an operator drill.</action>
  <verify>go test ./scripts -run 'Backup|Restore' -count=1 && bash -n scripts/backup-data.sh</verify>
</task>
</tasks>

<acceptance_criteria>
  - A backup can be listed and cryptographically verified before restore.
  - A restore drill proves the restored database/config are the selected snapshot and the app returns healthy.
  - Missing, mismatched, or unsafe snapshot inputs fail without changing live data.
</acceptance_criteria>
